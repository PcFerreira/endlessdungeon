# Browser builds

The Web preset exports the current game with Godot 4.7.2, the Compatibility renderer and single-thread WebAssembly. Desktop browsers need WebGL 2.0. The build uses the exact [official 4.7.2 templates](https://godotengine.org/download/archive/4.7.2-stable/), whose release archive SHA-256 is `f298490b8d44d934be425a5a65a51bf15f422428b229a06a6e11d9ffea248011`. The installer checks that digest and the two selected template ZIPs before use. Template files live in ignored `.tools/web-templates/`.

Run these commands from the repository root:

```sh
ruby tools/install_web_templates.rb
ruby tools/build_web.rb
.tools/node/bin/node tools/serve_web.mjs
```

Open `http://127.0.0.1:8000/` on this machine, or the printed LAN address from another machine on the same network. The host binds `0.0.0.0` by default. Set `WEB_HOST=127.0.0.1` to limit it to this machine and set `WEB_PORT` to change its port. Any installed modern Node can run the hosting helper. Use `ruby tools/build_web.rb --debug` for a debug engine. Exporting also runs Godot's resource indexing, so coordinate that window through `chat.md` while other agents work on imported resources.

The output is `builds/web/index.html` with its matching JavaScript, WebAssembly and PCK files. Keep their names together. The build rejects Godot versions that do not match the pinned templates and rejects script/export errors even when Godot exits zero. It checks the coordinated network manifest before and after export and verifies the exact manifest SHA-256 inside the pack. Logs stay outside the served directory in `builds/web-logs/`: `export.log` records the export and `pack-check.log` checks the exported pack. The public `build-report.json` records the content revision, exact raw and gzip sizes and file hashes. Gzip sidecars are generated for the local server and deployment servers that support precompressed assets. A new build replaces the published local directory after export and pack checks finish.

All recognised runtime resources are exported, including models selected from JSON queries. Explicit raw-file rules include the runtime JSON catalogues, locale data, network manifest, source records, licenses and credits. The editor export plugin in `addons/web_raw_files` adds raw SVG bytes alongside imported textures for icons read through `FileAccess`; including imported SVG paths in a filter alone does not preserve those source bytes. The pack check runs against an empty project directory, so source-disk fallbacks cannot conceal a missing file. It verifies every registered non-text asset resolves through `ResourceLoader`, checks exact raw-notice hashes, and rejects staging, development or server directories. It does not load every model and texture into memory. Normal browser gameplay provides a separate runtime check.

`import_assets`, development tools/tests, server code, source lore, docs, captured artifacts and other build output are excluded. Source archive downloads stay in staging. Runtime license/source notices are kept in the PCK and copied beside the build with `CREDITS.md`. `credits.html` links those notices and the [Godot license](https://godotengine.org/license/). Serve the entire output directory so players can read attribution files without unpacking the game.

The host serves only the build directory. It sends `application/wasm`, recognises gzip sidecars, supports `HEAD` and prevents directory traversal. Its default `0.0.0.0:8000` bind accepts LAN connections as requested; the gateway likewise listens on `0.0.0.0:8080`. The LAN development origin must be accepted by the gateway, and the client uses that hostname on port 8080. Public hosting uses the server deployment configuration and HTTPS. The [Godot Web export documentation](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html) explains the Compatibility/WebGL 2.0 requirement and single-thread export. This build does not require SharedArrayBuffer isolation headers.

For local multiplayer, start the authoritative server separately and enter `ws://127.0.0.1:8080/play` in the online lobby while the Web client is hosted on port 8000. Public HTTPS clients use `wss://` and the deployment's `/play` endpoint. The lobby's same-host default suits a reverse proxy that serves both paths. Public account state and map chunks are server data. Browser startup opens the lobby over an empty remote map; it never starts a local generated journey. Native offline journeys remain separate from accounts.

Audio starts after a player gesture. Browser sample playback has limitations for audio effects and continuous generated streams; stream playback has different latency. The current synthesized sound effects use buffered WAV samples, so these need actual playback review before a compatibility conclusion. Tabs may suspend game frames in the background, so online connections must recover after suspension. Fullscreen and pointer capture require a pressed input event. IndexedDB availability affects offline saves. Safari, Firefox, mobile controls, mobile performance, long sessions and browser storage eviction need separate acceptance. See the [documented Web limitations](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html#limitations).

The custom HTML shell also permits the requested single-thread preview over private LAN HTTP. Only the loader's secure-context diagnostic is removed on canonical RFC1918 or loopback hosts; WebGL, fetch and thread checks remain. Browser security properties and settings stay unchanged. Because AudioWorklet is unavailable on insecure LAN HTTP, this mode passes Godot's supported `--audio-driver Dummy` option before constructing the engine and displays “Sound is off in this LAN preview.” Godot may log unsupported sample-playback warnings in this silent mode. HTTPS and secure localhost retain the regular audio driver. `tools/web_shell.html`, `tools/web_lan_policy.mjs` and their focused tests keep this policy bounded. `ruby tools/update_web_launcher.rb` updates only an existing build's HTML and policy helper, then regenerates their compressed sidecars and hashes; it does not change the PCK or authority revision.

The accepted edition-4 release uses content revision `0fd5661110ae40af7f2ca9c25da835a3c3f4cc5266d6940796dadc77b4868ca4`. Its complete startup payload, including the private-LAN policy helper, measures 327,148,422 raw bytes and 258,846,077 gzip bytes, plus 209 separately served notice/source files. The isolated pack check resolves 4,042 dynamic resources. The matching authority runs from `.tools/runtime-release-0fd56611`, assembled from the manifest closure; future checkout edits cannot change this live worker's inputs. Its durable database is `server/data/world.sqlite`.

Actual Chrome accepted two different accounts simultaneously: private LAN HTTP/WS at `http://192.168.100.95:8000/` and trusted HTTPS/WSS through the temporary Cloudflare hostname. Both booted with zero local generation, received 25 server chunks and region metadata, rendered Lanternwake Commons, and showed the named other player. LAN keyboard movement changed the server-stored position from `[32,-4058]` to `[28.50690460205078,-4054.5087890625]`; the HTTPS peer displayed that move. Reloading LAN Chrome and pressing Resume remembered account restored the same player ID and exact stored position with a fresh 25-chunk bootstrap. A gateway shutdown during the isolated test returned an honest disconnected menu. The durable gateway was subsequently started without resetting its existing world or accounts and remains on `0.0.0.0:8080`. Logs and screenshots are in `artifacts/web-browser/final-*`.

These are two browser origins on this Mac; a physical second machine, production uptime, large player counts and long background suspension were not tested. LAN HTTP is silent and logged unsupported sample-playback warnings; the HTTPS browser logged no warnings or errors during this acceptance, but audible sound quality was not reviewed. The tunnel address is temporary and requires the local host, gateway and tunnel processes to remain running. The static host proxies only `/play` to its fixed localhost gateway and preserves the original Origin for gateway validation. Set `UPSTREAM_PORT` only when intentionally using another local gateway port.

The accepted local gateway is already running. To restart that same frozen release later, gracefully stop its existing process first and run the following from the repository root. Keep the database; update the origin list if the LAN IP or temporary tunnel hostname changes.

```sh
ENDLESS_DB="$PWD/server/data/world.sqlite" \
GODOT_BINARY="$PWD/.tools/Godot.app/Contents/MacOS/Godot" \
ENDLESS_HOST=0.0.0.0 ENDLESS_PORT=8080 PUBLIC_WORLD=1 \
ALLOWED_ORIGINS=https://crucial-dream-subsequently-kept.trycloudflare.com,http://127.0.0.1:8000,http://localhost:8000,http://192.168.100.95:8000 \
.tools/node/bin/node .tools/runtime-release-0fd56611/server/index.mjs
```

The static host command is `.tools/node/bin/node tools/serve_web.mjs`. A later tunnel launch can use `.tools/cloudflared tunnel --url http://127.0.0.1:8000 --protocol http2`; it assigns a new hostname that must be added explicitly to the gateway origin list. Assembly of a new release is a separate coordinated operation: check its manifest, run `node server/assemble_runtime.mjs . DESTINATION`, install the locked dependencies under `DESTINATION/server`, and export the matching client. See [server deployment notes](../server/README.md) for content upgrades and database backups.
